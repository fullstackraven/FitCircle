## Reviewed paths without the same initialization overwrite

- Profile stores scalar strings only on Save Profile. Home/Calendar/Routines/Reminders sidebar reads username and consumes temporary session flags; these reads do not rewrite profile records on mount. Sidebar session/cursor removal is intentional transient navigation behavior, not a fallback record save.
- pages/fasting.tsx, hydration.tsx and meditation.tsx explicitly save goal keys on confirmation; risks in associated shared goal documents are listed above. Reading a scalar for display alone does not prove an overwrite.
- utils/meditation-calc.ts returns [] for mismatched/malformed logs but does not persist that fallback; its goal setter is explicit. Consumers must not repurpose that empty display result as authoritative storage.
- lib/backup.ts validates incoming recognized values before writes, journals originals and performs recovery before React mounts. Invalid export sources fail closed. It is not an initializer default-store fallback. Existing rollback/permanent-storage-denial limitations remain; no backup behavior changes here.
- lib/pwa-update.ts operates on static caches/update state, not fallback fitness records. use-timer/use-focus/use-mobile/use-toast/useIOSViewportGuard and ScrollLockContext do not own persisted fitness initialization. Static CacheStorage/legacy IndexedDB are already covered by the registry; food readers/migration and backup are their relevant owners.
- Settings export/restore is explicit and validated; erase is an existing separately confirmed action, not an automatic malformed-data response. This PR adds no reset/erase operation.

## First implementation and remaining work

Protect workout initialization first because that document owns workouts, routines, logs and journals. Reuse the existing backup schema for common value validation, then require the collections needed by runtime readers. Preserve original parsed values rather than Zod-normalized output. Only a truly absent key may create a fresh document. Read/parse/shape failures abort rendering before effects commit, and a narrowly typed recovery boundary offers a raw copy, retry, and the existing Settings restore flow.

All other rows are tracked **open** follow-ups, ordered: cardio load/save ordering; hydration/meditation/fasting/measurement/reminder mount saves; dated food/catalog initialization; action-driven recovery/session/energy/supplement/goal/settings stores; calculator and customization. Split by domain, preserving related legacy key writers and fixtures. FC-004 food-save reporting, FC-005 stale writers and diagnostic issue #25 are not bundled. This PR must not be described as complete FC-003 remediation across the app.
