# Security, dependency and performance review

Executed npm audit (exit1) and npm audit --omit=dev --json (exit1). The first reports 37 affected package nodes:21high,13moderate,3low, 0 critical. The production-install tree reports24:14high,10moderate. Counts include propagation through dependents; they are not distinct vulnerabilities or demonstrated exploits. Exact installed versions, direct/transitive classification, advisory URLs/ranges and proposed fixes are in [dependency-advisories.json](evidence/dependency-advisories.json). No packages were upgraded.

`--omit=dev` is not a shipped-bundle exposure test. tailwindcss-animate is production-listed and brings Tailwind/build/watch/PostCSS chains into that tree; Vite is a dev dependency and does not run on Pages. recharts brings lodash into runtime dependencies. Review lodash advisory APIs and actual bundled callsites before claiming user input reaches a vulnerable function. Tooling advisories matter for developer-server exposure and untrusted build input, not a nonexistent hosted Express server. Split Vite/esbuild and CSS/Babel chains into independently verified updates. Actions use version tags, so immutable SHA pinning is a future supply-chain hardening candidate, not a proven compromise. Lockfile v3 has350 package entries, registry resolutions and integrity on every non-root entry.

React renders journal/profile/food text as text rather than HTML. The intentionally generated diagnostic dock HTML and static recovery DOM do not constitute arbitrary user-HTML injection. Backup uses narrow registered keys, structural validation and allowlisted plan keys and null-prototype maps; existing tests exercise pollution inputs, malformed values. Importer validates before writes, but Settings has no file-size preflight bound (FC-031); very large/deep files can exhaust local resources. No hosted AI, auth, database or nutrition API was found in active features. Fonts are bundled. Historical pasted code under attached_assets is inert reference, not instructions to execute or external scripts to load. No broad CSP was introduced: inline recovery/diagnostic code and worker/font requirements need a tested policy, not an unverified meta tag.

Backup JSON and source/date identifiers are sensitive; no automatic cloud upload is present. Manual Files/iCloud saving stays user-controlled. Console statements include journal fragments (FC-002), food names/search terms and migration diagnostics. Remove sensitive content in a narrow review without hiding actionable storage errors. No real backup contents were logged during this task.

Performance: build passes with an existing >500kB chunk warning. Large monolithic route imports and charts warrant measured lazy-loading analysis only after offline/deep-link tests. Food Tracker synchronously parses history and catalog on changes (FC-015), LocalFoodService builds an unused index (FC-028), calculator/macros poll every 2 seconds, and hooks recompute history frequently. These are source-identified hotspots, not measured device regressions. The current active catalog is465 foods; the historical backup dataset has29,766 foods and no runtime import. Both datasets were fully parsed, core fields/IDs/numeric signs examined; no duplicate IDs or missing core fields found. Structural validity does not certify nutritional truth. The random historical generator and unit assumptions require provenance/reference checks before any dataset regeneration.

No profiler trace on physical iOS, startup performance benchmark, penetration test, independent advisory-page validation, Firefox/WebKit run or production load test was performed. Existing Chromium frame-sample JSON is historical evidence only. Optimize after reproducible cold/warm timings and equivalence fixtures; do not alter food rankings/calculations for speculative speed.
