# Integration audit (before production changes)

Base: main 3113d29; Food Tracker 2.0 PR #53 and follow-ups #54–56 are merged.

- Measurements owns `fitcircle_measurements_history` arrays (weight lb, height inches, body fat %). Its hook silently substitutes empty history on parse failure and autosaves immediately. Scalar mirrors include `fitcircle_weight`, `fitcircle_height`, `fitcircle_body_fat`; `fitcircle_measurements` is another legacy summary.
- Goal ownership overlaps: `fitcircle_goals.targetWeight/targetBodyFat/weightGoalType`, legacy `fitcircle_goal_weight/bodyfat`, `fitcircle_weight_goal_type`, and legacy measurement-summary fields. Measurements gives individual keys precedence while goals-utils gives the unified object precedence and migrates on reads. use-goals has further duplicated legacy loading. Weight progress uses proximity ratios or summary fields instead of recorded starting/current history.
- Calculator reads the last array element, substitutes 170 lb/70 inches and male, polls every two seconds, and persists initial defaults even when settings are unreadable. Its Mifflin–St Jeor conversions are lb×0.453592 and in×2.54, with fixed activity multipliers and ±500 kcal/lb/week.
- PR #55 made `fitness_calc_target_*` the live Food Tracker target source. The new request supersedes automatic target adoption: these keys must remain recommendations/legacy accepted values, separate from explicitly confirmed `fitcircle_nutrition_goals`. The latter already has backup validation and metadata passthrough, so no new storage key is needed.
- Profile already resolves DOB over saved age and reports malformed records. Sex/gender is retained in the profile record but has no current editing control. Missing required inputs must be exposed, not guessed.
- Backup v2 preserves registered raw strings, supports legacy JSON and IndexedDB foods, and provides validated transactional writes/rollback. Keep all keys, optional metadata and formats; no data migrations. Existing same-tab events and native storage events can communicate updates without polling writers.

Planned precedence: valid dated history is authoritative; scalar/legacy summary measurements are used only when history is absent and labeled undated legacy. Unified explicit goals precede legacy fields; disagreements remain stored and visible. Malformed authoritative records block editing/recommendations rather than enabling fallback writes. A recorded starting measurement may support progress; no fabricated start. Confirmed nutrition goals always win. Without confirmed goals, existing legacy calculator targets remain labeled legacy until explicit adoption; newly calculated recommendations are read-only and never autosaved as confirmed goals.
